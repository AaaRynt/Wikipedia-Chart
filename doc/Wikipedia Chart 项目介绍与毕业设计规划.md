# Wikipedia Chart 项目介绍与毕业设计规划

## 1. 项目概述

Wikipedia Chart 是一个基于 Wikimedia 开放数据的 Wikipedia 条目访问量可视化应用。项目通过 Wikipedia Search API 和 Wikimedia Pageviews API 获取知识条目及其访问量时间序列，使用 Recharts 将数据呈现为可交互的多折线图，支持条目搜索、趋势对比、条件筛选、链接分享和数据导出。

项目现阶段以 React、TypeScript 和 Vite 为基础，已经具备完整的前端数据查询与可视化功能。

毕业设计将在现有项目基础上扩展为**多语言知识热度分析系统**，重点增加跨语言知识实体关联、统计分析、时间序列预测及历史回测，并引入 Next.js 服务端数据访问、缓存和动态图片分享能力。

系统以 Wikipedia 条目访问量作为知识关注度的可观测指标，不将访问量直接等同于社会总体关注度。

## 2. 当前项目情况

### 2.1 已实现功能

当前公开仓库主要面向英文 Wikipedia，已实现以下功能：

- **多条目对比：** 支持同时选择多个 Wikipedia 条目，在同一张折线图中比较访问量变化趋势。
- **实时搜索：** 接入 Wikipedia 搜索接口，展示条目标题、描述及缩略图，支持输入防抖、请求取消和 `Cmd/Ctrl + K` 快捷键。
- **预设对比组：** 提供编程语言、人工智能、科技公司、历史事件等主题的预设条目组合。
- **查询筛选：** 支持自定义日期范围、每日或每月粒度、访问设备类型及访问者类型。
- **URL 状态同步：** 将条目列表和查询条件编码到 URL 中，支持复制链接并恢复查询状态。
- **图表与数据导出：** 支持将当前图表导出为 PNG、SVG，以及将 Wikimedia API 响应导出为 JSON。
- **ChatGPT 跳转：** 根据当前查询条件生成分析提示词并打开 ChatGPT，不直接调用 OpenAI API。
- **主题切换：** 支持明暗主题，使用 Tailwind CSS 和 shadcn 风格组件构建界面。

### 2.3 当前系统结构

现有应用采用顶部导航、中间图表和底部筛选栏的单页布局。

- **Header：** 搜索、下载、ChatGPT、主题切换等操作。
- **Main：** 占据主要窗口空间的 Recharts 图表，负责数据显示、加载及空状态。
- **Footer：** 日期范围、时间粒度、访问方式及访问者类型筛选。

项目通过统一的 `TQuery` 状态管理查询参数，在浏览器中直接请求 Wikimedia 接口，并将多条时间序列按时间戳合并为图表数据。

当前尚未实现完整的多语言实体关联、统计分析算法、趋势预测或服务端缓存。

## 3. 多语言知识热度对比

毕业设计计划将系统扩展为两种独立但共用图表与筛选组件的对比模式，通过页面顶部的模式切换组件进行选择。

### 3.1 条目对比模式（Articles Comparison）

**多个不同词条，在单一 Wikipedia 语言版本下进行趋势对比。**

这是现有 Wikipedia Chart 功能的延续与扩展。

用户首先选择一个 Wikipedia 语言版本，再搜索并选择多个不同条目，在同一张折线图中比较其访问量变化。

例如：

- 语言：English Wikipedia
- 条目：JavaScript、Python、TypeScript
- 结果：三种编程语言的历史访问量趋势对比

该模式继续支持原有的搜索、筛选、预设组合、图表导出及 URL 分享。

### 3.2 语言对比模式（Languages Comparison）

**单个知识实体，在多个不同 Wikipedia 语言版本下进行趋势对比。**

这是毕业设计新增的核心功能。

系统利用 Wikidata 的唯一实体标识（QID）关联不同语言 Wikipedia 中描述同一知识实体的条目，并通过 Wikidata sitelinks 获取各语言版本的规范页面标题。

例如，用户搜索“人工智能”，系统确定对应的 Wikidata 实体，再取得其英语、中文、日语等 Wikipedia 条目，并查询各语言版本在相同时间范围内的访问量。

该模式计划支持八种 Wikipedia 语言版本：

| 语言     | Wikipedia 项目标识 |
| -------- | ------------------ |
| 中文     | `zh.wikipedia`     |
| 英语     | `en.wikipedia`     |
| 日语     | `ja.wikipedia`     |
| 德语     | `de.wikipedia`     |
| 法语     | `fr.wikipedia`     |
| 西班牙语 | `es.wikipedia`     |
| 俄语     | `ru.wikipedia`     |
| 意大利语 | `it.wikipedia`     |

并非每个知识实体都存在全部八种语言版本。系统应识别实际存在的 sitelinks，避免对不存在的页面进行无效查询。

中文 Wikipedia 的简繁转换属于同一 Wikipedia 项目的语言变体，不重复计算为独立数据源。

### 3.3 两种模式的共用能力

两种模式共享同一套时间序列数据结构、Recharts 图表、日期筛选、访问方式筛选、统计分析和导出功能。

模式之间主要存在以下区别：

| 维度           | 条目对比       | 语言对比           |
| -------------- | -------------- | ------------------ |
| 知识对象       | 多个条目       | 单个 Wikidata 实体 |
| Wikipedia 语言 | 单选           | 多选               |
| 搜索结果       | Wikipedia 条目 | Wikidata 实体      |
| 图表序列       | 不同条目       | 不同语言           |
| URL 标识       | 语言及条目列表 | QID 及语言列表     |

切换模式时，搜索和语言选择组件随之改变，公共筛选条件尽量保持一致。两种模式都继续支持 URL 状态映射和查询恢复。

系统界面国际化与 Wikipedia 数据语言分别管理，避免将界面显示语言与实际查询的数据来源混为一谈。

## 4. 时间粒度与数据处理

系统计划支持三种时间粒度：

- **每日（Daily）：** 直接使用 Wikimedia Pageviews 的每日访问量数据。
- **每周（Weekly）：** 基于每日数据按自然周聚合，对该周有效的每日访问量求和。
- **每月（Monthly）：** 使用 Wikimedia Pageviews 提供的每月访问量数据。

每周统计采用周一至周日的 ISO 周规则，并处理跨年周次、不完整周和缺失日期等情况。

不同条目或语言的访问量数据需要进行时间轴对齐、排序、去重及缺失值处理，以保证趋势对比和算法分析采用一致的数据口径。

## 5. 数据分析与算法

毕业设计计划在现有图表功能基础上增加统计分析、异常检测、相关性分析和时间序列预测。

### 5.1 统计分析 Dialog

顶部新增“数据分析”入口，通过 Dialog 展示分析结果，内部固定三个 Tab。

#### 概览（Overview）

展示当前查询区间内的基础统计指标：

- 总访问量
- 平均访问量
- 最大访问量及对应日期
- 最小访问量
- 区间增长率
- 不同条目或语言之间的统计指标对比

统计结果随查询对象、日期范围和时间粒度变化。

#### 异常检测（Anomaly Detection）

使用 **Z-score** 等统计方法检测访问量时间序列中的异常波动。

主要包括：

- 使用历史滚动窗口计算均值与标准差。
- 根据 Z-score 识别明显偏离历史水平的访问量。
- 列出候选异常日期、实际访问量和异常程度。
- 支持在主折线图中定位或标记异常点。

异常检测只判断数据在统计意义上的异常，不直接推断现实事件及其因果关系。

#### 相关性分析（Correlation Analysis）

使用 **Pearson 相关系数**计算不同时间序列之间的线性相关程度。

主要包括：

- 对齐不同条目或语言的有效时间序列。
- 计算两两序列之间的 Pearson 相关系数。
- 使用相关性矩阵展示分析结果。
- 支持查看指定两条序列之间的相关程度。

语言对比模式重点分析同一知识实体在不同语言 Wikipedia 中的热度变化关系。可结合访问量变化率进行分析，减少共同长期趋势对相关性结果的干扰。

相关性分析不用于证明不同语言用户群体之间存在直接因果联系。

### 5.2 趋势预测（Time Series Forecasting）

趋势预测直接集成到现有 Recharts 主折线图，不作为统计分析 Dialog 的独立 Tab。

系统根据用户选择的历史访问量区间，使用时间序列预测算法估计后续时间范围内的访问量。

计划采用：

- **季节性朴素预测（Seasonal Naïve）：** 作为预测效果比较的基准模型。
- **Holt-Winters 指数平滑：** 结合历史数据水平、趋势及适用的季节性规律生成预测结果。
- 对不满足季节性建模条件的数据，可采用不含季节项的指数平滑方法。

预测时间范围根据每日、每周、每月粒度提供合理的可选期限，并要求具备足够的历史样本。

主图表使用实线表示实际访问量，使用虚线表示预测访问量；启用预测后，X 轴向右扩展，并通过不同线型和区域标识区分实际数据与预测数据。

### 5.3 历史回测（Backtesting）

系统支持对已经发生的历史时间段进行预测回测。

例如，用户选择截至 2021 年 12 月的历史访问量，预测 2022 年上半年的访问量。由于该时间段的实际访问量已经存在，系统可以同时展示：

- 2021 年及以前的历史输入数据
- 对 2022 年上半年的预测曲线
- 2022 年上半年的真实访问量曲线

通过预测值与实际值之间的差异计算误差指标，包括：

- MAE（平均绝对误差）
- RMSE（均方根误差）

预测模型只能使用预测起点之前的数据进行拟合，回测区间内的真实数据仅用于结果评价，避免未来数据泄漏。

毕业论文可以通过不同知识实体、不同语言版本及不同历史区间的预测实验，比较算法效果，分析突发事件、长期趋势和周期性波动对预测准确性的影响。

预测结果不保证准确，研究重点包括算法的预测表现、适用条件和局限性。

## 6. Next.js 服务端架构

### 6.1 框架与部署

计划将当前 React + Vite 单页应用迁移到 **Next.js App Router**，继续使用 React、TypeScript、Tailwind CSS、shadcn 风格组件及 Recharts。

系统继续部署在 Vercel，使用 Vercel Functions 执行 Next.js 服务端逻辑。

前端仍负责搜索交互、查询状态、图表绘制和统计结果展示；服务端主要负责 Wikimedia 数据访问、参数校验、缓存及动态图片生成。

不计划引入用户注册登录、权限系统或业务数据库。

### 6.2 Wikimedia 服务端数据访问

将当前由浏览器直接请求 Wikimedia 的方式扩展为统一的 Next.js 服务端数据访问层。

主要职责包括：

- Wikipedia 搜索与 Wikidata 实体信息获取
- Wikimedia Pageviews 数据查询
- 请求参数校验及规范化
- 并发请求控制与错误处理
- 数据缓存和复用
- 向前端返回统一格式的查询结果

服务端数据接口主要使用 Next.js Route Handlers。

### 6.3 基于时间分片的缓存机制

计划采用 **Next.js 数据缓存与按自然月分片的时间序列缓存策略**，利用 Vercel 托管的缓存基础设施减少重复 Wikimedia API 请求。

缓存以 Wikipedia 项目、规范条目标题、时间分片、数据粒度、访问方式和访问者类型等参数作为区分依据。

例如：

- 用户 A 查询某条目 2025 年 1 月至 6 月的每日访问量。
- 服务端获取并缓存对应月份的数据。
- 用户 B 查询同一条目 2025 年 4 月至 8 月的访问量。
- 服务端复用此前缓存的 4～6 月数据，仅请求缺失或失效的时间分片。
- 最终将缓存数据与新获取的数据合并、按日期裁剪，再返回客户端。

缓存粒度独立于前端的条目对比和语言对比模式，使相同 Wikipedia 页面在不同查询组合之间也能共享缓存。

每日与每周查询可以共用每日访问量缓存，并通过聚合得到每周数据；每月查询可使用 Wikimedia 的原生月度数据。

对搜索结果、实体映射、最近访问量和历史访问量采用不同缓存有效期。缓存未命中、过期或被清除时，系统重新请求 Wikimedia。

初步不引入 Redis，优先使用 Next.js 和 Vercel 提供的数据缓存能力。

### 6.4 动态图表生成与分享

系统计划基于 Next.js 服务端能力实现动态图表图片生成，复用 Wikimedia 数据访问、时间序列处理和缓存机制，根据 URL 查询参数生成对应的静态图表。

该功能支持两种输出形式：

- Open Graph 预览： 通过 `ImageResponse` 生成适合社交平台链接预览的 PNG 图片，并使用 `generateMetadata` 动态配置网页分享元数据。
- SVG 图表嵌入： 通过 Route Handler 返回 SVG 图片，支持其他网站、Markdown 和 GitHub README 直接引用，并提供嵌入代码复制功能。

两种输出共用图表的数据处理与绘制逻辑，仅在尺寸、样式和输出格式上有所区别。现有浏览器端 PNG、SVG 文件下载功能继续保留。

- 顶部增加“条目对比 / 语言对比”模式切换。
- 搜索框和语言选择器根据当前模式切换行为。
- 中间保留占据主要窗口空间的 Recharts 折线图。

- 顶部增加“数据分析”和“趋势预测”等功能入口。
- 数据分析通过包含“概览 / 异常 / 相关性”三个 Tab 的 Dialog 展示。
- 趋势预测直接在主图表中以虚线扩展时间轴，并支持历史实际数据对照。

## 8. 系统总体定位

毕业设计最终形成一个以 **Wikimedia 开放数据为基础、支持跨语言知识实体关联与统计分析的 Web 系统**。

系统包含三个主要技术方向：

1. **多语言知识数据处理：** 通过 Wikidata QID 和 sitelinks 关联不同语言 Wikipedia 条目，实现多语言访问量查询与对比。
2. **时间序列统计与预测：** 实现统计概览、异常检测、Pearson 相关性分析、时间序列预测与历史回测。
3. **Web 系统设计与实现：** 使用 Next.js、React 和 Recharts 实现交互式数据可视化、服务端缓存、URL 状态分享及动态图片生成。

系统保留 Wikipedia Chart 原有的轻量交互风格，不以复杂的用户管理或后台业务系统为目标，而以开放数据获取、跨语言比较、统计分析、预测实验及可视化展示为核心。

**当前项目已经完成单语言多条目访问量可视化的基础功能；毕业设计计划新增的核心内容是多语言实体关联、统计与预测算法，以及 Next.js 服务端数据与分享能力。**
